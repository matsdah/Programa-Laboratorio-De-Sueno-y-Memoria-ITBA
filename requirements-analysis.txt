# ecosistema científico, y porque el techo numpy<2.6 que necesita numba vive acá
# y no tiene por qué atarle las manos a la Parte 1.

# **No son opcionales para correr la suite.** Se separaron cuando ningún test
# las importaba, pero desde el hito 10 test_complexity.py, test_connectivity.py
# y parte de test_entrega.py sí lo hacen, y sin ellas fallan. El CI las
# instala en los dos jobs.
#
# `mne` y `scipy` NO están acá: la Parte 1 también los necesita (mne lee
# BrainVision y EDF, scipy filtra), así que viven en requirements.txt.
#
# Instalar cuando se trabaje en psglab/analysis/:
#     pip install -r requirements-analysis.txt

-r requirements.txt

mne-connectivity>=0.6   # BSD-3  - conectividad de la señal
antropy>=0.1.6          # BSD-3  - complejidad (entropías, dimensión fractal)
# Las fases sugeridas (hito 75). Trae su clasificador adentro, sin descargar
# nada, y suma lightgbm (MIT), lspopt (MIT) y seaborn (BSD-3); el resto de lo
# que pide ya estaba. Medido: no mueve el techo de numpy de abajo.
yasa>=0.7               # BSD-3  - clasificador de fases de sueño

# El techo de numpy no es un capricho ni lo pide la Parte 1: lo impone esta
# capa. `antropy` necesita `numba`, que a su vez fija `numpy<2.6` y depende de
# `llvmlite`. numba y llvmlite son los paquetes que más tardan en publicar
# ruedas para un Python o un numpy nuevos, así que sin este techo el día que
# salga numpy 2.6 el resolvedor entra en un retroceso largo —o directamente no
# resuelve— y el CI se pone rojo sin que nadie haya tocado el código.
#
# Cuando numba soporte la versión siguiente, subir el techo acá y en ningún
# otro lado. requirements.txt queda sin techo a propósito: la Parte 1 no tiene
# este problema.
numpy<2.6
