PySide6>=6.6,!=6.12.0  # LGPL-3.0  - interfaz gráfica (Qt for Python)
# Exclusión puntual, no un techo genérico: dos corridas de CI en Linux/Python
# 3.11 abortaron con código 134 durante la construcción de la ventana. La
# traza de faulthandler señaló la traducción de `ConnectivityPanel` como el
# punto donde se detectó el fallo. Una comparación controlada posterior,
# también en Linux/CPython 3.11, midió cuatro setters Qt comunes: cada llamada
# consumió una referencia de `None` con PySide6 6.12.0; los mismos setters
# quedaron estables con 6.11.2. La traducción no fue la causa aislada. El
# diagnóstico y sus límites están en
# [docs/INCIDENTE_PYSIDE_6_12.md](docs/INCIDENTE_PYSIDE_6_12.md); el probe
# reproducible está en `scripts/diagnose_qt_refcount.py`.
pyqtgraph>=0.13     # MIT       - render rápido de las ondas
numpy>=2.0          # BSD-3     - base numérica
scipy>=1.11         # BSD-3     - filtros, PSD y estadística
mne>=1.6            # BSD-3     - lectura de BrainVision, EDF y otros formatos

# El piso de numpy es 2.0 como política de compatibilidad del proyecto. La
# versión se fija explícitamente aunque las operaciones de `band_power()`
# también existan en numpy 1.x: el piso común evita ampliar la matriz de
# versiones admitidas sin una decisión y cobertura de CI. El techo de la Parte
# 2 sigue viviendo en requirements-analysis.txt, por la dependencia de numba.

# ---------------------------------------------------------------------------
# POR QUÉ ACÁ NO HAY TECHOS GENÉRICOS
# ---------------------------------------------------------------------------
#
# Se evaluó ponerle un tope de versión mayor a PySide6, mne, scipy y pyqtgraph
# —una auditoría lo anotó como riesgo— y **la decisión fue que no**. Conviene
# dejar escrito el razonamiento para que no se vuelva a proponer sin él.
#
# El `numpy<2.6` de requirements-analysis.txt **no es una protección
# preventiva**: es una restricción que ya existe río arriba, porque numba la
# declara. Ponerla acá sólo la hace visible y evita que el resolvedor la
# descubra a fuerza de retroceder. Para estas cuatro no había una restricción
# equivalente río arriba; la exclusión puntual de PySide6 6.12.0 responde al
# fallo medido arriba, no a una dependencia.
#
# Un techo puesto por las dudas cuesta caro y no compra lo que parece:
#
#   - Bloquea actualizaciones legítimas, incluidas las de seguridad, hasta que
#     alguien se acuerde de subirlo.
#   - No evita la rotura: la esconde. El día que PySide6 7 rompa la interfaz,
#     preferimos enterarnos por el CI y no meses después, cuando el techo
#     finalmente se levante y nadie recuerde qué cambió.
#   - Necesita mantenimiento manual y sin fecha, que es exactamente el tipo de
#     tarea que este proyecto documenta como la primera en olvidarse.
#
# Lo que sí tenemos es la red que lo hace tolerable: el CI resuelve de nuevo en
# cada corrida sobre **tres sistemas operativos y dos versiones de Python**, así
# que una release rota aparece en horas y con la traza puesta. El precio
# aceptado es que el CI pueda ponerse rojo sin que nadie haya tocado el código.
#
# **Cuando eso pase, la respuesta no es un techo genérico**: es leer el fallo y
# o bien adaptarse, o bien agregar un tope **específico con el motivo medido**,
# que es el estándar que cumple el de numpy.
